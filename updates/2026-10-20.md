### 1. Database Review Resolution on `gitlab!262418`
- **Issue**: [`#633930`](https://gitlab.com/gitlab-org/gitlab/-/issues/633930) — *Optimize group count query to select only IDs in UserGroupsCounter*.
- **Reviewer**: Database maintainer `@Quintasan`.
- **Finding**: While single-user queries were fast, batches of 100 user IDs (as passed by `GroupCountResolver`) flipped the `project_authorizations` arm from a nested loop to a 55M-buffer, 85–137 second parallel hash join across all `projects` and `namespaces`.
- **Architectural Solution**: Replaced the project lookup with a `CROSS JOIN LATERAL` with `LIMIT 1`:
  ```sql
  SELECT g.id, pa.user_id
  FROM project_authorizations pa
  CROSS JOIN LATERAL (
    SELECT namespaces.id FROM projects
    INNER JOIN namespaces ON namespaces.id = projects.namespace_id
    WHERE projects.id = pa.project_id AND namespaces.type = 'Group'
    LIMIT 1) g
  WHERE pa.user_id IN (...)
  ```
- **Changes**: Updated `app/finders/user_groups_counter.rb`, added batch user ID spec in `spec/finders/user_groups_counter_spec.rb`, committed, and pushed to `community/hrlpavan-633930-optimize-user-groups-counter-query`. Updated the MR description with final SQL and replied to the database reviewer.
